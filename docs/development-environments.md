# Development environments outside synced folders

Keep source, data, tests and recreation instructions in the project. Put virtual
environments and generated caches outside OneDrive or other synchronized folders.
Do not move unique custom builds or research data into disposable caches.

For a checkout named `ecat`, a macOS example is:

```bash
python3 -m venv "$HOME/.venvs/ecat"
source "$HOME/.venvs/ecat/bin/activate"
python -m pip install -e ".[dev,app]"
python -m pip check
python -c "import ecat; print(ecat.__version__)"
```

Select that interpreter in your editor. To use it as a Jupyter kernel:

```bash
python -m pip install ipykernel
python -m ipykernel install --user --name ecat --display-name "eCAT (local)"
```

The macOS source launcher checks `~/.venvs/<lowercase-checkout-name>/bin/python`
before an environment inside the repository. `ECAT_PYTHON` explicitly selects an
interpreter. See [Workbench launchers](../apps/workbench/README.md).

Record the Python version and dependency versions alongside the project before
recreating an environment. Review dependency lists for credentials, personal
paths and editable entries before sharing them. Use the matching Python version,
install the recorded dependencies, then reinstall the checkout in editable mode.
The package's supported dependencies remain in `pyproject.toml`; a workstation
snapshot is not a universal installation requirement.

Generated bytecode, Matplotlib and test caches can be redirected with
`PYTHONPYCACHEPREFIX`, `MPLCONFIGDIR` and pytest's `-o cache_dir=...`. Store those
paths outside the synchronized source tree. Ordinary simulation uses the public
`[simulation]` extra; experimental custom backends are maintained separately.
